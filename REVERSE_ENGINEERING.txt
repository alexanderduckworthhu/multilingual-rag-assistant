--------------------------------------------------------------------------------
1. THE ONE IDEA (start here when lost)
--------------------------------------------------------------------------------
Question the whole app answers:

  "Given public WHO guidance in English and French, can I answer a user's
   question with citations, and refuse when the corpus does not support it?"

If a feature does not improve grounding, multilingual access, or measurable
retrieval, it does not belong. That filter stops INFJ overbuilding.

2. DATA / CONTROL FLOW (follow arrows with your finger)
--------------------------------------------------------------------------------

  data/sample/*.txt (+ optional data/raw from download_corpus)
           │
           ▼
     src/ingest/load_docs.py     ← reads .txt/.pdf + sidecar .meta.json
           │
           ▼
     src/ingest/chunk.py         ← RecursiveCharacterTextSplitter
           │
           ▼
     src/ingest/embed.py         ← multilingual-e5-small ("passage:" prefix)
           │
           ▼
     src/retrieve/store.py       ← Chroma upsert (cosine)
           │
           ▼
     data/processed/chroma/      ← persisted index
           │
           │  user question
           ▼
     src/retrieve/search.py      ← embed query ("query:" prefix) + top-k
           │
           ├── distance > threshold ──► refuse (no LLM)
           │
           └── grounded ──► src/generate/answer.py
                              ├── OPENAI_API_KEY? → gpt-4o-mini (temp 0)
                              └── else → extractive top passages
           │
           ▼
        app.py  → answer + expandable sources (EN/FR UI via src/i18n.py)


Mental model:
  INGEST    = "turn documents into overlapping chunks"
  EMBED     = "map meaning to vectors (same space for EN and FR)"
  STORE     = "persist vectors + metadata locally"
  RETRIEVE  = "find nearest chunks; decide if good enough"
  GENERATE  = "write only from those chunks, or refuse"
  EVAL      = "measure retrieval with labeled queries"

3. FILE MAP. WHAT EACH FILE OWNS
--------------------------------------------------------------------------------

src/config.py
  - Locked knobs: CHUNK_SIZE_CHARS, RETRIEVAL_TOP_K, MAX_COSINE_DISTANCE_TO_ANSWER
  - Reverse-engineer tip: change MAX_COSINE_DISTANCE_TO_ANSWER, re-ask an off-topic
    question, watch refuse vs answer flip

src/ingest/load_docs.py
  - Corpus loader: sample folder always works; raw folder optional
  - Sidecar *.meta.json holds doc_id, language, title, source_url
  - WHY WHO samples: bilingual, Geneva-relevant, short enough to debug

src/ingest/chunk.py
  - DocumentRecord → ChunkRecord list
  - chunk_id format: {doc_id}::c{index:04d}  ← used as citation tokens

src/ingest/embed.py
  - E5 prefixes are NOT optional cosmetics, model was trained with them
  - normalize_embeddings=True so cosine distance behaves cleanly

src/retrieve/store.py
  - One collection for both languages
  - metadata includes language so the UI can filter without a second index

src/retrieve/search.py
  - Returns (chunks, is_grounded)
  - is_grounded = best distance <= MAX_DISTANCE_TO_ANSWER

src/generate/prompts.py
  - Closed-book system prompt + citation requirement
  - This is your verbal interview script in code form

src/generate/answer.py
  - Orchestrates retrieve → gate → LLM or extractive
  - Extractive mode is intentional: portfolio demos must run without paid keys

src/eval/metrics.py
  - precision@k and MRR only, do not inflate claims with BLEU on answers

src/i18n.py
  - All Streamlit chrome strings EN/FR

scripts/build_index.py
  - Delete/recreate collection, upsert all chunks, write index_metadata.json

scripts/run_eval.py
  - Loads golden_queries.json, prints aggregate metrics, writes eval_report.json

scripts/download_corpus.py
  - Best-effort WHO topic page download into data/raw/
  - Not required for the demo; samples already prove the pipeline

app.py
  - Thin UI: question → primary Ask → answer panel → sources
  - Advanced options tucked away; answer language follows UI by default

src/styles.py
  - Fraunces + Source Sans 3, soft fade-ins, primary CTA emphasis

src/i18n.py
  - All human-facing EN/FR strings (UI + refusal / empty-index messages)


--------------------------------------------------------------------------------
4. ARCHITECTURE DECISIONS. THE WHY (interview depth)
--------------------------------------------------------------------------------

4.1 Chunking strategy
  WHAT: Recursive character splitting, size=800, overlap=120
  WHY: Policy prose has paragraphs and lists. Recursive split tries paragraph
       breaks first, then sentences, keeps chunks coherent without an LLM.
       Overlap is cheap insurance when an answer straddles two chunks.
  TRADE-OFF: Semantic / proposition chunking can be cleaner but adds another
       model and failure mode. For entry-level, explainability wins.

4.2 Embedding model
  WHAT: intfloat/multilingual-e5-small
  WHY: One vector space for English and French. Free. Runs on a laptop.
       Explicit query/passage prefixes give you something concrete to say in
       interviews ("I respect the model's training format").
  TRADE-OFF vs OpenAI embeddings: slightly weaker on niche jargon; you gain
       offline control and zero embedding cost. Good portfolio trade.

4.3 Vector store
  WHAT: Chroma persistent client, cosine space
  WHY: No Docker, metadata filters, inspectable on disk under data/processed.
  TRADE-OFF vs FAISS: FAISS is faster at huge scale you do not have.
  TRADE-OFF vs Pinecone: cloud cost + account friction for a demo.

4.4 LLM
  WHAT: gpt-4o-mini, temperature 0; extractive fallback without key
  WHY: Strong instruction following for citation prompts; cheap.
  TRADE-OFF: Generation quality is vendor-dependent, that is why you evaluate
       RETRIEVAL as your engineering claim.

4.5 Corpus choice
  WHAT: WHO guidance-style EN/FR documents (mental health, UHC, PHC)
  WHY: Geneva HQ signal for WHO/UN/consulting interviews; natural bilingual
       pairs; shorter than UNGA resolutions → better first eval loop.
  HOW TO EXPAND:
       1) python -m scripts.download_corpus
       2) Or drop PDFs into data/raw/ with a .meta.json sidecar
       3) python -m scripts.build_index
       Future: WHO IRIS open-access PDFs; UN Digital Library resolutions as v2.


--------------------------------------------------------------------------------
5. FRENCH + ENGLISH IN THE SAME INDEX
--------------------------------------------------------------------------------
Myth: "I need two indexes, one per language."
Reality with multilingual-e5: meanings align across languages in one space.

What you store per chunk:
  text, embedding, metadata={language, doc_id, title, source_url, ...}

What you can do at query time:
  - language=None  → search both (default; shows cross-lingual power)
  - language="fr"  → hard filter for French-only passages
  - answer_language independent → reply in FR even if sources were EN

Why this matters for Geneva roles:
  Staff constantly switch languages. Showing cross-lingual retrieval is a
  feature you can demo live ("I asked in French, it cited the English UHC note").


--------------------------------------------------------------------------------
6. HALLUCINATION-REDUCTION STRATEGY (say this out loud)
--------------------------------------------------------------------------------
Do not claim the model "never hallucinates." Claim you engineered friction:

  (1) Retrieval gate, weak match ⇒ refuse before generation
  (2) Closed context, prompt forbids outside knowledge
  (3) Citations, every factual sentence ends with [chunk_id]
  (4) Temperature 0, less improvisation
  (5) Transparent UI, raw passages always visible
  (6) Measured retrieval, precision@k + MRR on a golden set

If an interviewer pushes: "What if the retrieved chunk is wrong?"
Answer: "Then generation can still fail, that is why I evaluate retrieval
separately and keep the human in the loop via visible sources."


--------------------------------------------------------------------------------
7. EVALUATION. HOW TO READ THE NUMBERS
--------------------------------------------------------------------------------
Golden set: data/eval/golden_queries.json
  Each row: query, relevant doc_id prefixes, optional language_filter

Metrics:
  Precision@k = (# relevant among top k) / k
    → "Of what I showed the user, how much was on-topic?"

  MRR = average of 1/rank_of_first_relevant
    → "How quickly do I surface something useful?"

Commands:
  python -m scripts.build_index
  python -m scripts.run_eval
  → data/processed/eval_report.json

Portfolio tip: screenshot the metrics + one refused question + one cited answer.
That triad beats a long architecture essay.

--------------------------------------------------------------------------------
9. DEBUG PLAYBOOK (when something feels wrong)
--------------------------------------------------------------------------------
Symptom: Empty index warning in sidebar
  Fix: python -m scripts.build_index

Symptom: French question retrieves nothing useful
  Check: language filter set to "en" by mistake? Clear to "Both".
  Check: E5 prefixes still applied in embed.py

Symptom: Fluent answer with no citations
  Check: OPENAI_API_KEY path, prompts.py must be used
  Check: you are not in extractive mode (extractive lists passages instead)

Symptom: Always refusing
  Loosen MAX_DISTANCE_TO_ANSWER slightly in config.py, rebuild not required
  (threshold is applied at query time)

Symptom: Always answering off-topic questions
  Tighten MAX_DISTANCE_TO_ANSWER; confirm gate in answer.py runs before LLM

Symptom: Eval metrics look random
  Rebuild index after changing chunk size; golden relevant_ids are doc prefixes
